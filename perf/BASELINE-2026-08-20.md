## Access constraints (stated, not worked around)
- No SSH / WP filesystem; PHP ships via WPCode snippets (hash-verified paste). No Redis control (WP.com Atomic has built-in object cache; server-side caching changes limited to snippet-level transients). Cloudflare zone cache rules not exposed through available tooling → CDN phase documented as recommendations only. DB indexes: no direct SQL access → not attempted.
- Rollback: repo is git (every change one commit, CDN pin moves atomically); WPCode edits are hash-verified with prior content recoverable from repo mirrors in `wpcode/`; WP.com keeps automated backups (Jetpack activity log).
